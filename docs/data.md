robomimic's machine-generated (`mg`) and `paired` datasets are not included: their demos include failures, which a
transfer that searches for success would not reproduce.

Each file keeps its dataset's demo names, lengths, and filter keys: the `train` and `valid` splits, the
`20_percent` and `50_percent` subsets, and, for the mh datasets, the operator and quality subsets (`better`,
`okay`, `worse`, `better_operator_1`, ...); the MimicGen datasets have none. The human demonstrations were recorded in robosuite on CPU MuJoCo, whose
physics differ from this simulation's, so replaying a demo's recorded actions here drifts from its recorded
states. `robomimic.data.transfer` closes that gap: from each demo's first state, it rolls out perturbations of
the recorded actions in parallel worlds, a few steps at a time, and keeps those whose states stay closest to the
recorded ones, until the demo succeeds. The files hold the simulated states, the actions that produced them,
and the rewards and dones they earned; `success` marks the demos that succeed.

The demos that the search does not bring to success are made another way, and the packed files record each
demo's `origin`. Each such demo is first *replayed*: from its first state, in its own model, each step commands each
arm toward the gripper pose that the recorded action targets from the recorded state, starting from wherever the
simulated gripper is, so the arms follow the recorded plan without drifting from it; small noise on the arm actions
is added where the exact poses fall short. A MimicGen demo that no replay brings to success is *generated* anew from
its first state by `robomimic.data.generate`. Between 0.1% and 5% of each MimicGen dataset is replayed, two Pick
Place D0 demos (293 and 299) are generated, and one Lift mh demo (233) and 28 Transport mh demos are replayed.

## Building robomimic datasets

The packed files store no observations. Build them into robomimic low_dim hdf5 datasets, with `obs` and
`next_obs` for robomimic's training code:

```sh
uv run python -m robomimic.scripts.make_datasets          # all of them, into ~/data/robomimic_warp/<task>/<type>/low_dim_v15.hdf5
uv run python -m robomimic.scripts.make_datasets --tasks lift_ph --output <dir>
```

The datasets have the released low_dim datasets' layout, observation keys, and shapes. `obs[t]` is the POMDP's
observation of recorded state `t`, and `next_obs[t]` that of state `t + 1`; the state after a demo's last
action is not recorded, so its last `next_obs` observes the simulated outcome of that action. Load a packed
file directly with `robomimic.data.hdf5.unpack_demos`, which writes the hdf5 layout without observations.

## Generating demonstrations

`robomimic.data.generate` runs MimicGen's data generation in the POMDP, for a variant whose demos do not transfer
well. It splits a few source demos, transferred into the POMDP, into object-centric subtask segments, as MimicGen's
task specs define them, and replays each segment with the gripper's target poses carried into the frame of the
segment's object in a new reset, through the arm controller with MimicGen's action noise. Successful demos are kept,
one per reset, each with a `model_file` holding its reset's fixture poses:

```sh
uv run python -m robomimic.scripts.transfer_demos --dataset ~/data/mimicgen/source/mug_cleanup.hdf5 --output mug_cleanup_source_warp.hdf5
uv run python -m robomimic.scripts.generate_demos --task mug_cleanup_d1 --source mug_cleanup_source_warp.hdf5 --output mug_cleanup_d1_generated.hdf5
```

The generated demos are new demos, not MimicGen's. Every dataset in `datasets/warp` is transferred, none generated.

## Packed format

An npz of arrays, concatenated over demos in `names` order. Datasets larger than 95 MB are split, in demo order,
into parts `<name>.part0.npz`, `<name>.part1.npz`, ..., each in this format with all the filter keys;
`robomimic.data.hdf5.read_packed` and `unpack_demos` take the dataset's name `<name>.npz` and join its parts:

| key | contents |
|---|---|
| `env_args` | the dataset's environment metadata, a JSON string |
| `names`, `lengths` | demo names and their numbers of steps |
| `models`, `model_index` | each distinct robosuite model xml once, and each demo's index into them |
| `success` | whether each demo succeeds |
| `origin` | how each demo's states were made: `transferred`, `replayed` (MimicGen's recorded gripper targets re-executed), or `generated` (new from the demo's first state) |
| `step/states` | flattened MuJoCo states `[time, qpos, qvel]` before each action, float32 |
| `step/actions`, `step/rewards`, `step/dones` | per step; actions and rewards float32 |
| `step/<annotation>` | the dataset's other per-step annotations, unchanged: `interventions`, `policy_acting`, `user_acting` |
| `mask/<key>` | the demo names of each filter key |

## The released datasets

`robomimic.data.registry` lists the released robomimic v1.5 datasets on Hugging Face, and
`robomimic.scripts.download_datasets` downloads them into `$ROBOMIMIC_DATA` (default `~/data/robomimic_v15`):

```sh
uv run python -m robomimic.scripts.download_datasets --tasks square --dataset_types mh --hdf5_types raw low_dim
```

`robomimic.scripts.transfer_demos` transfers any of them; `get_dataset_info`, `split_train_val`, and
`filter_dataset_size` inspect and split robomimic hdf5 datasets as robomimic's scripts do.
